# Development

Day-to-day backend dev loop. For deployment see [`DEPLOYMENT.md`](DEPLOYMENT.md). For the wire contract see [`API.md`](API.md).

## Prerequisites

- Python 3.12
- [`uv`](https://github.com/astral-sh/uv) (any recent version; 0.5+ tested)
- Docker + Docker Compose v2 (recent — the compose file uses `service_completed_successfully` and other v2.13+ features)

## First-time setup

```bash
cd services/api
uv venv
uv pip install -e ".[dev]"
```

## Run the tests

```bash
cd services/api
uv run pytest tests/unit -v              # fast, no DB
uv run pytest tests/integration -v -m integration   # spins up Postgres via testcontainers
uv run ruff check . && uv run ruff format --check .
uv run mypy
```

## Run the API locally

Two ways:

**Direct (fastest for hot-reload):**

```bash
# In one terminal: a Postgres for the api to talk to
cd infra/prod
cp .env.example .env       # any values, only the ones api reads matter
docker compose up -d postgres

# In another: the api with uvicorn auto-reload
cd services/api
export DATABASE_URL='postgresql+asyncpg://smartscale:<your-pw-from-.env>@localhost:5432/smartscale'
export DEVICE_KEY='dev-secret'
export OPENAI_API_KEY='sk-...'    # only needed for /v1/voice/match
uv run python -m smartscale_api.main
```

**Compose (closest to production):**

```bash
cd infra/prod
cp .env.example .env
docker compose up -d postgres
docker compose run --rm migrate
docker compose up -d api
curl http://localhost:8000/v1/healthz   # not directly exposed; use docker compose port api 8000
```

## Layout

```
services/api/src/smartscale_api/
  routes/       Thin FastAPI routers. One file per resource.
  domain/       Pure functions. No I/O. Fully unit-testable.
  repos/        Postgres access (SQLAlchemy async).
  schemas/      Pydantic request/response models.
  voice/        Whisper client + fuzzy matching helpers.
  auth.py       DeviceKeyMiddleware (X-Device-Key gate).
  config.py     Settings (pydantic_settings).
  db.py         Async engine + sessionmaker factory.
  ids.py        ULID helpers.
  app.py        Composition root: create_app() -> FastAPI.
  main.py       Uvicorn entry point.
```

## Adding an endpoint

1. Add a router under `routes/`.
2. Add request/response Pydantic models under `schemas/`.
3. Pure business logic goes in `domain/`. Repo calls go in `repos/`.
4. Write unit tests under `tests/unit/`.
5. Write integration tests under `tests/integration/` if there's DB or HTTP behavior worth asserting.
6. Regenerate the OpenAPI spec: `cd services/api && uv run python scripts/generate_openapi.py`.
7. Update `docs/API.md` if the wire contract changed.

## Migrations

Alembic config: `services/db/alembic.ini`. Migrations: `services/db/migrations/versions/`.

```bash
cd services/db
DATABASE_URL=postgresql+psycopg://localhost/smartscale uv run --project ../api alembic revision --autogenerate -m "<short-change>"
```

SQLAlchemy autogen doesn't catch every check constraint or partial index — hand-edit the generated file as needed.

Migrations run automatically on every prod deploy via the `migrate` compose service. Locally: `docker compose run --rm migrate` from `infra/prod/`.

## Auth

`X-Device-Key` (writes + product reads) or `X-Admin-Key` (admin) on every non-health endpoint. `/v1/healthz` is auth-exempt. See [ADR 0009](adr/0009-no-public-product-reads-mvp.md) and [ADR 0011](adr/0011-shared-secret-device-key.md).

## OpenAPI

The contract lives at `services/api/openapi.json` and is regenerated by `services/api/scripts/generate_openapi.py`. CI's `contract.yml` re-runs the script and fails if the committed file drifts from what FastAPI generates.
